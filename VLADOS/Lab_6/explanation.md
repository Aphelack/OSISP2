# Лабораторная 6 — scanner

## Идея лабораторной

Программа `scanner` — простое приложение на C, демонстрирующее разбор/обход данных (сканирование). Код расположен в `main.c` и компилируется в один исполняемый файл.

## Сборка

Собирается через `Makefile`:

```bash
cd Lab_6
make
```

Сборка использует флаги `-Wall -Wextra -O2` и определяет `-D_POSIX_C_SOURCE=200809L`.

## Запуск

Запустите из каталога `Lab_6`:

```bash
./scanner
```

Параметры запуска зависят от задания — посмотрите `main.c` для описания аргументов и поведения.

## Структура файлов

- `main.c` — исходный файл
- `Makefile` — правила сборки

## Примечания

- Компиляция оптимизирована (`-O2`) и ориентирована на POSIX.
- Для отладки можно изменить флаги в `Makefile` (убрать `-O2`, добавить `-g`).

## Привязка к коду (объяснение для непрофессионала)

1) Что делает эта программа
	- `scanner` по заданному IP-адресу проверяет диапазон TCP-портов и сообщает, какие порты открыты (принимают соединения). Это упрощённый порт-сканер.

2) Как запускать
	- Программа ожидает три аргумента: IP-адрес, начальный порт и конечный порт. Пример:

```bash
./scanner 192.168.1.1 1 1024
```

3) Подход: неблокирующие сокеты и проверка группой
	- Для ускорения сканирования программа открывает несколько сокетов одновременно (пакетом). Для каждого порта создаётся сокет и устанавливается флаг `O_NONBLOCK`, чтобы вызов `connect` не блокировал программу.
	- Затем программа вызывает `select` с множеством файловых дескрипторов для записи: когда сокет готов к записи, это означает, что попытка соединения либо установлена, либо завершилась ошибкой. После `select` для каждого готового сокета читается значение ошибки через `getsockopt(..., SO_ERROR)`: если ошибка 0, соединение установлено и порт считается открытым.

4) Почему так делается (простыми словами)
	- Если выполнять `connect` в блокирующем режиме последовательно для каждого порта, сканирование займёт очень много времени. Неблокирующий режим + `select` позволяет одновременно ждать множества попыток соединения и быстро определить, какие из них прошли.

5) Ограничения и практические замечания
	- Для прослушивания/сканирования низких портов (<1024) иногда нужны повышенные привилегии, но для простого сканирования как клиент это обычно не требуется.
	- Сеть, брандмауэры или цели, настроенные на игнорирование входящих попыток, могут не отвечать — тогда порт будет считаться закрытым или неотвечающим.
	- Значения `MAX_BATCH` и `TIMEOUT_SEC` находятся в `scanner.h`. Увеличение `MAX_BATCH` повышает параллелизм, но требует больше дескрипторов и памяти; уменьшение `TIMEOUT_SEC` ускорит сканирование, но может привести к ложным отрицательным результатам в медленной сети.

6) Взаимосвязь файлов
	- `scanner.h` — содержит общие константы и структуру `port_target`, описывающую порт и соответствующий сокет.
	- `main.c` — реализует логику: создание сокетов, установка неблокирующего режима (`set_nonblocking`), попытка `connect`, запуск `select`, проверка `SO_ERROR` и закрытие сокетов.

## Пример запуска

```bash
cd Lab_6
make
./scanner 127.0.0.1 1 1024
```

При работе вы увидите строки вида `Port 80: OPEN` для обнаруженных открытых портов.
