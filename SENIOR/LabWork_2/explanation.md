# LabWork 2. Преобразование CSV в SQL

## Идея лабораторной

Лабораторная показывает, как shell-скрипт может читать текстовый файл, извлекать из него структуру данных и генерировать другой текстовый формат. В этой работе входной CSV превращается в набор SQL-команд `INSERT`.

Формат входного файла принят такой:

```csv
employees
id,name,age,position,salary
1,Иванов Иван,30,Инженер,1500.50
```

Первая строка — имя таблицы, вторая строка — список колонок, остальные строки — данные.

## Как запускать

Из каталога `LabWork_2`:

```bash
chmod +x csv2sql.sh
./csv2sql.sh data.csv
```

Если второй аргумент не указан, результат будет записан в `output.sql`. Можно явно указать имя выходного файла:

```bash
./csv2sql.sh data.csv employees.sql
```

Для файла `data.csv` результат выглядит примерно так:

```sql
INSERT INTO employees (id,name,age,position,salary) VALUES (1, 'Иванов Иван', 30, 'Инженер', 1500.50);
INSERT INTO employees (id,name,age,position,salary) VALUES (2, 'Петров Пётр', 25, 'Менеджер', 1200.00);
```

## Привязка к коду

Скрипт берет входной файл из первого аргумента, а выходной — из второго. Если второго аргумента нет, используется `output.sql`:

```bash
INFILE=$1
OUTFILE=${2:-output.sql}
```

Конструкция `${2:-output.sql}` означает: взять `$2`, если он задан, иначе подставить `output.sql`.

Перед обработкой проверяется, существует ли входной файл:

```bash
if [[ ! -f "$INFILE" ]]; then
    echo "Использование: $0 <файл.csv> [выходной_файл.sql]"
    exit 1
fi
```

Если файла нет, скрипт выводит подсказку и завершает работу с ошибкой.

Имя таблицы и список колонок читаются из первых двух строк:

```bash
TABLE_NAME=$(sed -n '1p' "$INFILE" | xargs)
COLUMNS=$(sed -n '2p' "$INFILE" | xargs)
```

`sed -n '1p'` печатает только первую строку, `sed -n '2p'` — вторую. `xargs` здесь используется для удаления лишних пробелов по краям.

Основная генерация SQL выполняется через `awk`:

```bash
awk -v table="$TABLE_NAME" -v cols="$COLUMNS" -F',' '
NR > 2 && NF > 0 {
    val_list = ""
    for (i = 1; i <= NF; i++) {
        gsub(/^[ \t]+|[ \t]+$/, "", $i)
```

Параметр `-F','` говорит `awk`, что разделитель полей — запятая. Условие `NR > 2` пропускает первые две строки, потому что они уже использованы как имя таблицы и колонки.

Каждое значение приводится к SQL-виду:

```awk
if ($i == "" || $i == "NULL") {
    v = "NULL"
} else if ($i ~ /^-?[0-9.]+$/) {
    v = $i
} else {
    gsub(/\047/, "\047\047", $i)
    v = "\047" $i "\047"
}
```

Пустая строка и строка `NULL` становятся SQL-значением `NULL`. Числа остаются без кавычек. Остальные значения оборачиваются в одинарные кавычки. Если внутри строки есть одинарная кавычка, она удваивается, потому что в SQL это способ экранирования.

Список значений собирается через запятую:

```awk
val_list = (val_list == "" ? "" : val_list ", ") v
```

После этого печатается готовый SQL:

```awk
printf "INSERT INTO %s (%s) VALUES (%s);\n", table, cols, val_list
```

Весь вывод `awk` перенаправляется в файл:

```bash
}' "$INFILE" > "$OUTFILE"
```

## На что обратить внимание

Это учебный CSV-парсер. Он корректно показывает идею преобразования строк, но не является полноценным обработчиком CSV. Например, строка:

```csv
3,"Сидоров, Алексей",28,Аналитик,1800.75
```

будет разделена по запятой внутри кавычек, потому что `awk -F','` не понимает CSV-кавычки как отдельный синтаксис. Поэтому для реальных CSV с кавычками, переносами строк и запятыми внутри полей лучше использовать специализированный CSV-парсер.

Файл `bad.csv` полезен для демонстрации ограничений: в нем есть строки с недостающими и лишними полями, а скрипт не сверяет количество значений с количеством колонок.
