# LabWork 4: IPC Server-Client с FIFO каналами

## Описание

Программа реализует сервер-клиентскую архитектуру с использованием **именованных каналов (FIFO)** для межпроцессного взаимодействия (IPC).

### Архитектура

```
                    ┌─────────────────┐
                    │     SERVER      │
                    │  (server.c)     │
                    │                 │
                    │  ┌───────────┐  │
              ┌─────┼──┤ server.fifo ├──┼─────┐
              │     │  └───────────┘  │     │
              │     │                 │     │
              ▼     │                 │     ▼
    ┌──────────────┴─┴─┴──────────────┴──────────────┐
    │                                                │
    ▼                                                ▼
┌─────────┐                                    ┌─────────┐
│ CLIENT  │                                    │ CLIENT  │
│  (PID   │                                    │  (PID   │
│   1234) │                                    │   5678) │
└─────────┘                                    └─────────┘
```

| Файл | Описание |

## Типы запросов

| Команда | Описание |
|---------|----------|
| `echo <text>` | Вернуть текст обратно |
| `upper <text>` | Преобразовать в ВЕРХНИЙ регистр |
| `lower <text>` | Преобразовать в нижний регистр |

## Логирование

Сервер ведёт лог всех операций в файле `server.log` с временными метками:

```
[2026-03-31 12:34:56] Server started, FIFO created: /tmp/lab4_server_fifo
[2026-03-31 12:34:57] Processing request from PID 1234, type=1, data="hello"
[2026-03-31 12:34:57]   -> UPPER: "HELLO"
[2026-03-31 12:34:57] Response sent to PID 1234
```

## Протокол взаимодействия

1. **Клиент** создаёт персональный FIFO: `/tmp/lab4_client_<PID>_fifo`
2. **Клиент** отправляет запрос через общий `/tmp/lab4_server_fifo`
3. **Сервер** читает запрос, обрабатывает его
4. **Сервер** отправляет ответ через персональный FIFO клиента
5. **Клиент** получает ответ, удаляет свой FIFO

## Структура запроса

```c
typedef struct {
    int client_pid;              // PID клиента
    request_type_t request_type; // Тип запроса
    char data[MSG_SIZE];         // Данные
} request_t;
```

## Особенности реализации

- Сервер обрабатывает запросы **последовательно** (один за другим)
- Для поддержки множественных клиентов используется **персональный FIFO** для ответов
- Сервер корректно обрабатывает ситуацию, когда все клиенты закрывают соединение (перезапуск FIFO)
- Поддерживается корректное завершение по сигналу (Ctrl+C)
- **Игнорирование SIGPIPE** — сервер не завершается при записи в закрытый клиентский FIFO
- **Атомарность записей** — все сообщения меньше PIPE_BUF (4096 байт), данные не перемешиваются
- **Детальное логирование** — все операции записываются в `server.log` с временными метками

## Обработка ошибок и сигналов

| Сигнал/Ошибка | Обработка |
|---------------|-----------|
| `SIGINT` (Ctrl+C) | Корректное завершение, очистка FIFO |
| `SIGTERM` | Корректное завершение, очистка FIFO |
| `SIGPIPE` | Игнорируется (не завершает сервер) |
| `EINTR` | Повторная попытка операции |
| `EPIPE` | Клиент отключился, запись пропущена |
